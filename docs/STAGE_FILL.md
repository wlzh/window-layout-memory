# 台前调度横屏自动铺满

v0.3.0-preview.1 / build 5。菜单开关默认关闭，升级不自动开启。

## 使用

在菜单勾选“台前调度：横屏自动铺满（拖左边缘调整留白）”。系统台前调度也必须开启。
点击缩略图、Command+Tab或激活窗口后，前台普通窗口稳定下来才铺满所在横屏的可用工作区，不移动到其它屏幕。竖屏和正方形屏幕不处理。

左侧默认预留200逻辑点（pt，不是Retina物理像素）。这只是可调整的初始值，不是系统缩略图区的测量结果，不保证适配所有缩略图设置。

拖动窗口左边缘中段，松手后记住新的留白。例如200变为150，窗口向左扩大50，上下和右侧重新对齐。避免从左上/左下角或标题栏拖动；角落调整仍视为临时自由布局。留白按完整显示器组合和显示器ID保存，同屏不同应用共用，最少保留320 pt窗口宽度。

拖动标题栏或其它边缘可以临时自由调整，不会立即拉回；下次激活时再铺满。刚切屏或自动移动后有短暂保护期，建议等窗口稳定再拖动。

菜单栏和常驻Dock占用区域被避开；自动隐藏Dock时窗口可延伸到对应屏幕边缘，Dock临时浮现可能覆盖窗口，这是系统行为。变化在屏幕配置通知或下一次激活/核对时应用，没有周期轮询。系统或应用的最小/最大尺寸限制可能导致无法精确贴边，状态面板会报告移动未到位，不循环强制重试。

## 与原布局的关系

铺满优先于横屏窗口的普通布局自动恢复；模式中的横屏窗口不进入普通布局候选，也不自动覆盖原基准。仅留白更新写入独立偏好。关闭开关停止铺满，不立即移动窗口，原基准仍可通过恢复功能使用。

暂停、排除应用、权限失效、镜像/无效显示器配置仍阻止自动操作。最小化、原生全屏及后台台前调度组不强制展开。导入备份后铺满开关关闭，需重新确认。

## 兼容性与隐私

macOS没有在本项目中使用的公开台前调度开关查询接口。目前只读`com.apple.WindowManager`的`GloballyEnabled`偏好；这不是Apple保证兼容的接口。读取失败或类型不明确时不铺满，状态面板显示未知。系统升级后需要重测。

工作区基于[NSScreen.visibleFrame](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe)，配合只读Dock自动隐藏偏好处理边缘。不开录屏、不抓缩略图、不记录键盘；沿用鼠标按下/松开监听和合并后的AX核对，无新增空闲定时器。200 pt不是实时识别缩略图宽度。

实机及自动化证据见[测试报告](TESTING.md)，不将几何单元测试当成系统端到端验收。
