# 台前调度横屏自动铺满

功能始于v0.3.0-preview.1 / build 5；当前为v0.3.0-preview.10 / build 16候选，实测未通过前不发布。新安装默认关闭，升级保留开关偏好。

按用户最新要求，先对齐目标位置，再请求目标尺寸。最多4次、间隔150 ms核验尺寸，最后读回完整矩形确认是否到位。不记录、判断或缓存窗口成功历史。

尺寸被拒绝、忽略或限制时停止并报告，不循环重试或自动回滚。因此受限制窗口仍可能停在已移动的位置，不能保证所有窗口铺满或零抖动。位置写入失败、失焦、权限变化、用户按下鼠标或配置改变时停止后续调整。

不使用原生最大化、分步挪动或鼠标模拟。无新缓存、定时器或磁盘写入。普通恢复不变。应用自身可能响应尺寸请求而改变几何，不能承诺系统级原子变化。

为处理应用的尺寸写入兼容性，原AXEnhancedUserInterface明确为true且系统VoiceOver/Switch Control未开启时，仅在本次调整期间临时关闭该应用属性，结束后恢复；未知/false不改。恢复失败会报告，不永久禁用辅助功能，不写入偏好、不新增轮询。恢复后再次读取最终几何。具体应用是否支持仍以实测为准。

授权变化在下一次应用事件进入有限稳定期后恢复扫描，无需必须手动刷新。版本验收见[状态](STATUS.md)。

默认100 pt只影响没有自定义值的屏幕；已有拖动记忆保留。build 9移除单独设为100 pt的菜单项，仍可拖左边缘重新学习。

## 子窗口与排除

“台前调度铺满 → 应用例外”支持勾选当前运行的应用，也可用“从文件选择应用…”逐个选择.app（包括未运行应用）。按Bundle ID及显示名称持久保存，不存安装路径、不启动应用；工具/应用重启后仍有效，应用移动路径但Bundle ID不变也继续有效。未运行的已选应用仍显示勾选，可点击取消。最多200个，不按应用名称猜测身份，身份改变需重新选择。

这是独立于“自动记忆与恢复 → 完全忽略应用”的设置。新设置只在铺满模式中阻止该应用当前横屏的自动铺满及恢复/学习旁路，仍保留窗口观察，普通模式的布局功能不被关闭。原有全局排除会停止该应用的全部布局核对，两者不会互相改写。应用级铺满排除优先于子窗口开启和窗口级规则，适用于所有显示器组合。

“同时铺满子窗口”默认关闭，仅在横屏铺满总开关开启时可编辑。系统台前调度关闭时不生效。识别依据为窗口角色、子角色和直接父级，不按窗口数量、打开顺序、标题、尺寸或图片扩展名猜测。多个独立Finder/浏览器标准窗口不因为是第二个窗口而被排除。

- 父级为应用的标准窗口正常铺满。应用若把图片窗也暴露成这种独立窗口，自动识别无法区分，需要手动排除。
- 父级为窗口/Sheet的标准子窗口仅在子窗口开关开启时铺满。
- 对话框、Sheet、浮动/系统面板及明确报告AXModal的窗口始终不作为铺满目标；父级或角色读取未知也不铺满，开启子窗口选项不放宽这一安全边界。AXModal不支持时不据此推断模态关系。
- “台前调度铺满 → 当前窗口暂不铺满”按运行时窗口身份临时排除。关闭窗口后完整扫描会清理，应用退出或工具重启后失效。
- 有非空AXIdentifier时提供“台前调度铺满 → 按标识排除此窗口…”，确认后按应用bundle、identifier、role、subrole精确持久匹配，不按标题匹配。应用可能复用标识，可能同时影响同标识主窗口；菜单明确提示，“管理窗口例外”可逐条撤销。没有可靠标识时仅提供临时排除。
- 手动排除优先于子窗口开关。规则跨显示器组合生效，但不修改任何组合的布局基准、历史、留白或应用级排除。应用级排除仍优先停止扫描。
- 总开关和系统台前调度均开启时，被排除的当前横屏窗口同时跳过自动恢复和候选/留白学习，防止旁路挪动；普通模式、竖屏的原有布局功能不因此禁用。主动关闭铺满恢复普通流程，不等于永久排除所有窗口管理。

设置变更使在途操作失效，尺寸/位置写入仍需通过权限、焦点、鼠标、显示器组合与最新策略检查。已发生的移动不自动撤销。菜单使用已核对的前台窗口缓存，不为打开菜单新增AX扫描。

## 使用

在菜单勾选“台前调度铺满 → 横屏自动铺满”。系统台前调度也必须开启。
点击缩略图、Command+Tab或激活窗口后，前台普通窗口稳定下来才处理。自动恢复开启且窗口唯一匹配当前组合基准时，先按记录选择显示器：目标横屏铺满该屏工作区，目标竖屏/正方形恢复原保存几何但不铺满。没有记录、匹配有歧义或自动恢复关闭时，只允许在当前横屏铺满，不猜测跨屏。后台窗口仍需用户激活，不自动切组。

左侧默认预留100逻辑点（pt，不是Retina物理像素）。这只是可调整的初始值，不是系统缩略图区的测量结果，不保证适配所有缩略图设置。

拖动窗口左边缘中段，松手后记住新的留白。例如200变为150，窗口向左扩大50，上下和右侧重新对齐。避免从左上/左下角或标题栏拖动；角落调整仍视为临时自由布局。留白按完整显示器组合和显示器ID保存，同屏不同应用共用，最少保留320 pt窗口宽度。

设计行为是：拖动标题栏或其它边缘可临时自由调整，继续使用同一窗口时不立即拉回；切到其它应用/窗口再切回，稳定后尝试重新铺满。左边缘调整留白属于单独路径，松手后记忆并对齐其余三边。刚切屏或自动移动后有短暂保护期，建议等窗口稳定再拖动。

build 7合入保护期内激活请求保留修复。微信第二实例仍有AX尺寸写入未到位，不能保证所有应用“切回来一定铺满”。一次尝试失败后不持续抢窗口。完整证据见[测试报告](TESTING.md)。

菜单栏和常驻Dock占用区域被避开；自动隐藏Dock时窗口可延伸到对应屏幕边缘，Dock临时浮现可能覆盖窗口，这是系统行为。变化在屏幕配置通知或下一次激活/核对时应用，没有周期轮询。系统或应用的最小/最大尺寸限制可能导致无法精确贴边，状态面板会报告移动未到位，不循环强制重试。

## 与原布局的关系

保存记录决定显示器归属，铺满只替换目标横屏的尺寸与坐标，不取消归属记忆。此路径不自动覆盖原基准和历史；左边缘留白仍存独立偏好。临时拖到另一屏不会立刻搬回，下次激活再回保存屏幕。关闭开关停止铺满，不立即移动窗口，原基准可通过普通恢复使用。

当前“撤销最近恢复”针对普通布局恢复事务，铺满路径不加入该撤销记录；不要把它当作铺满专用撤销。若需回到原基准，先关闭铺满，再显式恢复已保存的前台窗口。

暂停、排除应用、权限失效、镜像/无效显示器配置仍阻止自动操作。最小化、原生全屏及后台台前调度组不强制展开。导入备份后铺满开关关闭，需重新确认。

## 兼容性与隐私

macOS没有在本项目中使用的公开台前调度开关查询接口。目前只读`com.apple.WindowManager`的`GloballyEnabled`偏好；这不是Apple保证兼容的接口。读取失败或类型不明确时不铺满，状态面板显示未知。系统升级后需要重测。

工作区基于[NSScreen.visibleFrame](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe)，配合只读Dock自动隐藏偏好处理边缘。不开录屏、不抓缩略图、不记录键盘；沿用鼠标按下/松开监听和合并后的AX核对，无新增空闲定时器。100 pt不是实时识别缩略图宽度。

实机及自动化证据见[测试报告](TESTING.md)，不将几何单元测试当成系统端到端验收。
