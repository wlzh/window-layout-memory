# 自定义窗口例外

当前更新：0.3.0-preview.19 / build 26。微信聊天记录例外统一为类型规则：匹配以“的聊天记录”结尾的非空对象标题及“搜索聊天记录”，按应用标识和标准窗口类型隔离，横竖屏共用。旧聊天记录精确标题例外读取时合并；图片、PDF和其它规则不变。微信主窗口不在此规则内。安装与实测状态见 docs/TESTING.md（项目内对应测试报告）。

## 聊天记录（build 26新增）

激活微信聊天记录窗口后，在“台前调度铺满 → 铺满例外”选择“永久排除此应用的聊天记录窗口”。已保存列表显示“类型 = 聊天记录窗口”，点击撤销。不同联系人和群聊不必重复添加；“搜索聊天记录”也共用此条。两个微信实例按bundle独立，不自动互相扩大。

旧聊天记录精确标题规则读取时合并，下一次正常保存时写入新格式；没有旧规则则不会自动启用。此功能依据标题模式，不保证识别所有语言或未来微信版本。不读取聊天正文。不匹配微信主窗口、空对象标题或带文件扩展名的标题。

## 文件类型（build 24新增）

目标标题以受支持扩展名结尾时，菜单提供“永久排除此应用的 PDF 文件窗口”等入口。它按应用bundle、角色、子角色和扩展名匹配，扩展名不区分大小写，例如a.pdf与b.PDF命中同一条规则。仍保留“永久排除标题”供用户只排除一个具体文件名。

不会读取文件内容、文件路径或扫描磁盘；只依据窗口标题末尾的扩展名。无扩展名、标题为“文件.pdf - 应用”、末尾带空格等情况不匹配，不做宽泛猜测。支持：pdf、doc、docx、xls、xlsx、ppt、pptx、txt、md、csv、rtf、png、jpg、jpeg、gif、webp、heic、bmp、tif、tiff、svg、mp4、mov、m4v、mp3、wav、m4a、zip、rar、7z。相同应用中的所有同类型窗口均受影响，其它应用不受影响。

文件规则在已保存列表中显示“文件类型 = .pdf”等，点击撤销，重启后保留，与其它永久规则共用200条上限。不会自动把既有文件名精确标题规则扩大成文件类型规则；本机微信PDF规则的转换是用户明确授权的一次性迁移。聊天记录类型采用上文独立迁移策略。

图片窗口硬编码已移除。“图片和视频”这种没有文件扩展名的固定窗口，使用精确标题例外即可。已有用户例外保留；未配置规则时按通用窗口策略处理。

## 精确标题

自0.3.0-preview.16 / build 23起，可在原菜单中手动添加精确标题规则，无须新增设置窗口或每次修改代码。

1. 激活要排除的窗口，等待核对完成。
2. 打开“台前调度铺满 → 铺满例外”。
3. 在当前窗口分组核对目标应用，点击“永久排除标题：实际标题”。勾选代表已保存。
4. 已添加的窗口例外中会显示应用及“标题 = …”，点击即可撤销。

规则精确匹配应用bundle、窗口角色、子角色及整个标题，大小写、空格都不自动忽略，不做包含或正则匹配。标题为空、全空白或超过1024字节时不可添加。保留原按AX标识永久排除及会话临时排除。所有永久窗口规则共用200条上限，重复点击撤销，不重复追加。

build 23历史案例为微信“群聊的聊天记录”，当时按精确标题匹配。build 26起该类标题使用上文聊天记录类型规则，不再逐联系人添加；其它标题仍采用精确匹配。

规则横屏、竖屏共用，优先于“同时铺满子窗口”。在已启用的铺满方向同时阻止自动恢复/学习旁路；普通模式和显式手动恢复不属于此排除范围。添加不会立即缩小或移动窗口，也不会删除原布局；用户可以随后手动调整。

规则持久保存并随布局备份导入导出；精确标题可能包含私人信息，分享备份前注意检查。规则使用互斥的exactTitle、fileExtension、windowCategory或AX标识。聊天记录类别不保存联系人名称。旧版不支持windowCategory，降级时应恢复升级前备份，不直接用旧版打开新数据。

真实添加、安装及验证状态见[测试报告](TESTING.md)。自动化模拟验证不能替代辅助功能授权后的真实窗口核验。
