# 兼容性与已知缺口

状态日期：2026-09-09。代码存在、测试通过和稳定支持是不同结论。

本次工作版本为v0.3.0-preview.9 / build 15候选。撤回未通过实机验收的分步挪动实验，恢复目标尺寸先核验、成功才写位置的规则；兼容处理仅在应用启用AXEnhancedUserInterface且系统辅助技术未开启时临时使用，结束恢复。未知或不支持的属性不强改。不能将这些保护宣称为全部应用兼容；安装实测见[状态总览](STATUS.md)。

build 11授权后实机复现Telegram由较窄窗口变成1920 pt全宽，并报尺寸未达到目标。build 12不再调用原生最大化；只是消除这条副作用路径，原位置限制导致的尺寸失败仍可能存在。ChatGPT在同次授权后观察到1820 pt宽及100 pt左留白，不证明所有应用或所有切换均通过。

v0.3.0新增台前调度横屏铺满。系统开关只读WindowManager偏好，不是公开稳定API；未知状态不执行。当前100 pt是可调整初值，不是缩略图尺寸识别。Dock/菜单栏与应用尺寸限制见[说明](STAGE_FILL.md)，新功能实机门禁独立记录。

build 9依赖应用提供AX窗口角色与直接父级。父级缺失或类型未知时保守跳过，可能连普通主窗口也暂不铺满；图片窗口若声明为应用下独立标准窗口则无法自动区别。临时排除依赖运行时身份，持久排除依赖应用/AXIdentifier/角色精确一致；标识改变会失配，标识复用可能影响其它主窗口。子窗口开关不会开放对话框、Sheet或浮动面板。不能以自动测试替代用户常用应用的图片窗口实测。

v0.3.0-preview.1实测中，WPS、第二微信实例、系统设置出现未完全贴边报告，原因尚未确定；Arc、ChatGPT、微信主窗口和访达已有目标几何一致的观察。不得宣传所有应用兼容，受控复测仍待完成。

build 6后续受控复测确认：第二微信实例可用原生缩放达到1920×1055，但工具写入目标1774×1055时位置改变、尺寸未达到目标。该项仍失败；不能将AX无错误码当成功，也不能认定只因最大尺寸限制。“保护期丢激活”和“本屏铺满跳过归属恢复”均合入build 7；不意味着微信尺寸写入兼容问题被解决。

v0.2.0新增预览已完成114核心、32协调器及12项原生合成检查。真实AX数据对照、最新台前调度完整切换和性能仍需实机验收；预览不表示后台窗口当前可见或真实遮挡层级，详见[预览说明](PREVIEW.md)。

## 未完成项

1. 自动学习仅覆盖具有鼠标标题栏/边缘证据的调整，其余变化需手动保存；并非所有输入方式均可无感学习。
2. 已实现手动显示器映射复制和重命名；不维护自动别名表，不猜测未知显示器。
3. 未实现完整窗口角色规则编辑器。
4. 未实现启动第三方应用或重建文稿/标签。
5. 临时AX错误且无任何几何变化时最多重试一次；部分写入或应用尺寸约束不重试。
6. 各应用AX通知支持与实际台前调度几何尚未逐项验证。
7. Engine已增加假服务集成回归；真实AX适配器、GUI没有完整自动化覆盖报告。
8. 实际插拔、登录/唤醒、代表性双模式性能和8小时驻留尚未验收。

## 范围外

Spaces、原生全屏、台前调度分组顺序、完整遮挡层级、任意应用内部会话与未保存内容恢复。

仅通过核心测试不得声称“完全满足需求”。详见 [测试报告](TESTING.md)。
