# Telegram Lite动态标题与显示器归属

0.3.0-preview.20 / build 27。

Telegram Lite的窗口标题会随聊天对象和未读数变化，旧版本可能为同一窗口保存多个角色。当前组合的目标仍按显示器ID隔离，不跨组合借用。

## 匹配与保护

同一运行期优先使用既有窗口绑定。跨运行时，仅对org.telegram.desktop且当前组合只有一条保存角色、当前只观测到一个窗口、双方没有文档或稳定标识的情况，允许忽略标题匹配。其它应用及原生Telegram客户端不启用此规则。多个窗口不会走单窗口回退；有准确标识或精确标题时仍可正常匹配。

已有Telegram记录但不能解析身份时，不在当前屏幕自动铺满并新增基准。自动铺满保存若要改变已匹配记录的displayID，必须有手动跨屏证据；否则保留原显示器。关闭自动恢复时仍可在本地铺满，但不会因此改写原跨屏归属。主动手动保存不受此自动保存限制。

该规则不是通用主窗口识别。如果应用只暴露某个子窗口而不暴露原窗口，单窗口假设仍可能不成立；保留现有应用与窗口例外。不承诺所有Telegram弹窗都能自动识别。

## 历史记录合并

维护工具 `scripts/consolidate-telegram.rb` 默认dry-run，必须明确文件、组合ID和目标显示器ID。只合并该组合的Telegram Lite弱标识记录，选择最后一条已保存到指定显示器的基准，清空动态标题，保留其记录ID和几何。其它窗口、组合、历史与设置不变。遇到稳定标识、文档、锁定布局或目标不存在时拒绝。只有退出应用并传入--apply才写入；生成原始文件备份后原子替换。

不要对其它组合直接重复合并：真实多窗口或不同目标显示器需要先由用户确认。本次用户只确认当前Mi Monitor组合的目标。

## 验收

测试包括新会话动态标题、未读数变化、多窗口和多角色拒绝、原显示器优先恢复、标题变化不增加基准、本地自动铺满不覆盖跨屏基准，以及既有手动跨屏更新和重启恢复回归。实机及发行状态见[测试报告](TESTING.md)。
