# v0.3.0-preview.6

2026-09-09，build 10，schema 1。开发预览，尚未发布。

## 修复

新增“横屏铺满排除应用”：从当前运行列表勾选，或用文件选择器选择.app。按Bundle ID和名称保存，应用/工具重启后保持，未运行应用仍可取消。应用路径不保存，不启动所选应用；最多200个，重复标识不重复添加。与“排除应用（全部布局功能）”独立，普通模式继续保留布局功能。旧schema 1偏好缺省迁移为空列表，旧版再次写入可能丢失新偏好，降级前请备份。

尺寸优先流程中，某些应用在原坐标扩大时被屏幕右边/下边限制，因而永远无法通过尺寸核验。现在仅在同屏、几何可读、原位置无法容纳目标时，查询窗口按钮是否明确提供AXZoomWindow，最多执行一次非全屏原生缩放；随后确认空间、设置尺寸、核验尺寸，再对齐位置。

没有动作不猜测，不用AXPress或模拟点击。焦点、鼠标、权限、设置或显示器组合变化仍取消；跨屏目标不走该回退。原生缩放本身可能改变大小和位置，不能保证失败时完全不动，不能保证所有应用都最大化。

## 证据与限制

build 9实机Telegram曾报尺寸失败，受控原生缩放后达到Q2789上的(-1820,25)、1820×1055，留白100 pt。它不是被子窗口策略直接排除。微信尺寸失败尚未完成等价受控验证。此次没有改变子窗口识别规则、100 pt默认、布局/历史记录结构或schema编号；仅新增应用排除偏好。

验证及安装结果见[测试报告](../TESTING.md)、[状态](../STATUS.md)。AXZoomWindow动作也有[工具开发者说明](https://forum.soundflow.org/-7223/click-ui-element-with-modifier-key-and-without-being-tied-to-a-specific-app)，但运行时仍以窗口实际枚举结果为准，不将其作为所有macOS/应用都支持的保证。
