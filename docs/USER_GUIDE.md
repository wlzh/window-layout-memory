# 使用指南：开发预览

当前菜单适用于v0.3.0-preview.9 / build 14，完整分组、入口和禁用规则见[菜单导航](MENU.md)。常用预览/保存/恢复/撤销/暂停保留在第一层；登录启动和重新核对位于“设置与诊断”。

build 10：“台前调度铺满 → 应用例外”可从运行列表勾选，或点“从文件选择应用…”选择.app。以Bundle ID保存，应用/工具重启后保留，未运行应用仍可在列表取消。只排除铺满，与“自动记忆与恢复 → 完全忽略应用”不同；不会清除原布局记录。

build 9新增默认关闭的“同时铺满子窗口”，以及“台前调度铺满”中的当前窗口临时排除、有标识窗口的持久排除和逐条撤销。应用可能把图片窗暴露成普通独立窗口，需手动排除；无标识时不能可靠跨重启匹配。完整边界见[铺满说明](STAGE_FILL.md)。默认留白统一100 pt，删除单独设为100 pt的菜单项，保留已记忆自定义值。

build 14同屏铺满改为边缘渐进调整：已对齐的边在每个核验步骤保持目标，右下角已贴边时向左上扩展；不先整窗搬到最终左侧、不使用原生最大化。AX位置与尺寸分开写，仍可能短暂抖动或部分调整，失败即停止。跨屏铺满仍尺寸先核验，普通恢复不变。授权后下次应用事件会自动恢复核对，无需手动刷新。

当前公开版本与未发行修复、安装状态见[状态总览](STATUS.md)。以下操作说明不代表所有应用已通过实机验收。

## 关于应用

菜单选择“关于窗口布局记忆…”，查看当前版本、构建号、作者X @wlzh、网站869hr.uk及GitHub、使用文档、版本记录、MIT协议。链接仅在点击时交给默认浏览器打开。重复选择会回到同一个窗口，关闭即释放关于资源；不暂停布局服务、不修改保存记录，也不需要辅助功能授权。界面和明暗主题示例见[关于窗口](ABOUT.md)。

## 台前调度横屏铺满

build 7起，自动恢复开启且窗口唯一匹配当前组合记录时，先回记录中的显示器，横屏再铺满、竖屏恢复保存几何。未记录的应用不会自动获得显示器归属；后台组仍要逐个激活。临时手动跨屏后，下次激活会回到保存屏幕；若要永久更改基准，先关闭铺满、调整并保存，再开启。

v0.3.0起可从菜单开启“台前调度铺满 → 横屏自动铺满”。默认关闭；系统台前调度开启时生效。左侧默认100 pt，拖左边缘中段调整并松手后记忆，按显示器组合和显示器隔离，同屏应用共享。标题栏或其它边缘可临时自由调整，下次激活再铺满。原布局不会被覆盖，竖屏不处理。完整规则、Dock行为及限制见[使用说明](STAGE_FILL.md)。

## 布局预览

菜单栏选择“布局预览…”。窗口矩形按多屏实际关系绘制，选择后查看坐标、大小、读取时间及唯一匹配差值。其它组合只能查看独立保存布局。关闭释放预览资源，不影响原有记忆服务。详见[布局预览说明](PREVIEW.md)。

## 安装与权限

将归档中的应用放到 `/Applications/Window Layout Memory.app`。当前为ad-hoc签名、未公证预览，只使用可信来源，不建议关闭系统安全防护。

打开后点击“授权辅助功能”，在系统设置中由用户开启权限，切换到目标应用后自动恢复核对；也可返回应用手动点“重新核对”。不要求录屏、管理员或关闭SIP。终端启动二进制与Finder启动的权限上下文可能不同，以运行中应用状态和实际读取为准。

权限缺失时空列表不等于没有窗口。更新签名后可能需要重新授权。

本机build 6安装初期曾未授权，后续用户已重新授权，这是两个不同时间点。文档整理不要求重新授权。开发修改先在工程内测试，合并后统一安装，减少ad-hoc签名更新次数；必要更新无需每次另行确认，但系统要求的授权仍由用户操作。

## 建立基准

1. 按习惯摆好当前显示器组合中的窗口。
2. 依次激活各目标窗口，每个停留约2秒；仅核对真实前台普通窗口。
3. 在菜单中选择“保存已核对窗口（数量）”，建立当前配置的记录。
4. 后续激活更多窗口，再保存可合并。固定布局可锁定基准。

候选仅在会话内存在；切换显示组合、暂停或退出会清理未确认候选，需要先保存。已确认基准不因关闭窗口被删除。

自v0.1.0-preview.2起，新安装默认启用“自动记忆与恢复 → 自动记忆手动调整”。升级保留已保存的偏好；旧数据缺少此字段时默认关闭，需从菜单自行开启，并非每次升级都强制关闭。仅在前台窗口标题栏或缩放边缘观察到鼠标按下、松开后几何稳定时自动保存；自动核对必须同时开启。事件合并后约2秒写盘，期间避免切屏或退出；以“已自动记忆”状态为完成依据。没有鼠标证据的键盘调整、首次摆好的窗口和过快拖动可能只形成候选，请手动保存。锁定基准始终禁止覆盖。

台前调度开/关使用同一流程。台前调度各组需用户激活，软件不会点击缩略图；普通桌面的合法小窗口不会仅因尺寸被过滤。

## 恢复与角色

先激活目标窗口，再从菜单选择“恢复当前窗口”。状态面板如果在前台，要先回到目标应用。自动恢复默认关闭，开启需确认；开启后窗口激活/显示配置稳定时尝试匹配恢复。

隐藏、最小化、后台组窗口等待激活，不强制展开。焦点、几何、权限或显示配置变化可能取消操作。仅AX临时无法完成、实际几何完全未变且鼠标未按下时，延迟250毫秒重试一次；部分写入或尺寸限制不重试。菜单可立即取消待恢复并暂停，即使磁盘写入繁忙也会立即阻止后续移动；存储可用时同时保存关闭自动恢复设置。

同标题或同质多窗口有歧义时跳过，不能凭顺序猜。可在同应用目标窗口前台时，从“布局管理 → 关联已保存窗口”选一个角色。会话内绑定有效，重启后仍需要可区分的身份线索。

## 显示器组合

保存单位是**整个显示器组合**，不是显示器数量，也不是单台显示器。组合键包含所有屏幕的稳定UUID、位置、分辨率逻辑尺寸、缩放、旋转与主屏标记，不依赖枚举顺序或型号名称。

例如“内屏+A”“内屏+B”“内屏+A+B”“内屏+C+D”是四份独立布局。即使都包含同一Mac内屏，其上的应用、窗口位置和大小也各自记录。编辑其中一份不会更新其它组合的内屏窗口。遇到未见过的组合不会仅因为屏幕数量相同就套用其它布局。重新启动后仍按完整组合键匹配。

单/双/三屏分别建立基准。身份、排列或缩放变化可能生成新配置；没有记录时不借用别的配置。不修改显示器设置。更换扩展坞/接口后，可从“布局管理 → 从其它显示器组合映射”逐一指定旧屏幕对应的当前屏幕；不得重复分配目标。不自动按型号猜测。复制保留旧配置，替换当前配置前保留历史，完成后保持暂停且不搬动窗口。减少屏幕导致无法一对一映射时，请为新组合单独建立基准。镜像配置当前安全拒绝。菜单支持当前布局重命名。

## 保护与数据

- 锁定阻止基准更新，不阻止候选观察。
- 历史每配置最多20份、总200份；恢复历史只改基准，不立即移动窗口。
- 撤销只针对普通布局恢复记录中的同代际、同有效前台窗口移动；切屏使旧撤销失效，台前调度铺满目前不加入撤销记录。
- 排除和暂停阻止相关自动操作，不删除已保存基准。
- 私人JSON导出含窗口标题和文稿路径，不要公开。
- 导入前先导出旧数据；导入替换库，保持暂停且自动恢复关闭，需用户继续。

数据：`~/Library/Application Support/WindowLayoutMemory/layouts.json`。目录0700、文件0600。损坏时阻止覆盖，先备份损坏文件再从可信导出恢复。

## 登录、退出与卸载

登录启动单独选择，系统可能要求批准。软件不自动启动其它应用，也不重建文稿、标签或未保存内容。

关闭面板后仍在菜单栏运行；再次打开应用可显示面板。从菜单退出才停止监控。

卸载前取消登录启动并退出，再将应用移到废纸篓。数据默认保留；确认不再需要后可自行备份并删除上述数据目录，在辅助功能设置移除应用。
