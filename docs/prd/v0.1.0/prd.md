状态：用户已确认需求与技术方案，开发预览已实现。部分核心自动化子项已测；完整42项验收尚未关闭，实际证据见 [TESTING](../../TESTING.md)。

## 1. 目标与范围

作为经常连接、断开外置显示器的 Mac 用户，我希望各显示器组合分别记住我的窗口布局，切换组合后无需逐个重排，并且重新登录后仍保留这些习惯。

软件应尊重自由摆放，不强制平铺，不在完成一次恢复后持续把用户拖动的窗口拉回原位。

### 范围内

- 普通应用窗口的尺寸、位置、屏幕归属、屏幕内相对比例。
- 单屏、多屏、横竖屏、不同缩放与排列、主屏切换及内屏开合产生的配置变化。
- 台前调度启用时的普通窗口，含处于非当前组的窗口在再次激活后恢复。
- 台前调度关闭时的普通桌面窗口，以及运行中开启/关闭台前调度；不能仅为台前调度环境设计。
- 自动记忆、手动基准、历史回退、锁定、暂停、应用排除。
- 睡眠唤醒、重新登录、应用与窗口延迟出现。

### 范围外

- 多桌面 Spaces、原生全屏、台前调度分组与组顺序的重建。
- 操纵显示器硬件布局、分辨率或旋转设置。
- 恢复浏览器标签内容、未保存文稿、任意应用内部会话。
- 自动关闭窗口、退出应用、强制切换用户工作组。
- 无法由系统授权接口控制的窗口不承诺可恢复，必须逐项报告。

### 成功指标（发布门槛，不是当前结果）

- 关键流程 `1 → 2 → 3 → 2 → 1` 连续执行 10 轮，不发生跨配置污染或基准覆盖。
- 20 次台前调度切换不得把任何侧边预览尺寸记为正常布局。
- 可控制且身份明确的窗口恢复后，位置和尺寸与目标各相差不超过 4 个逻辑点；应用最小尺寸限制须单独报告。
- 3 次重新登录、10 次睡眠唤醒后，基准仍存在；窗口在可访问后完成恢复或得到明确失败结果。
- 所有 P0 自动化回归通过；实机门禁单独报告，未执行不得视为通过。

## 3. R01 显示器组合

不能仅按显示器数量识别布局。内屏+A 与内屏+B 必须能够保存不同布局。同一组屏幕的排列、缩放或主屏变化必须得到明确处理，不得静默套用错误配置。

首次遇到的组合不擅自重排。允许用户将当前布局确认为该组合的基准。没有历史单屏布局时，不得宣称能够推断用户的单屏偏好。

显示器更换接口、扩展坞或出现相同型号设备时，身份不确定应请求映射，不得仅凭型号自动搬动。

镜像模式不视为多个可独立放置窗口的屏幕；不支持的配置须停止恢复并解释。

## 4. R02 普通桌面与台前调度

不开启台前调度是完整支持的基础场景，记录、恢复、自动学习、单/多屏切换、重新登录和性能预算均不能缺失。

运行中开启或关闭台前调度不清空布局、不把系统切换动画产生的位置视为用户偏好。默认共用当前显示配置的布局；若两种模式下窗口可用区域不同，适配结果不是新的已确认基准。

用户无需关闭台前调度。侧边预览、系统覆盖层、菜单、提示气泡、工具浮层不作为普通窗口布局记录。

后台组窗口真实几何不可访问时，保留最后可信记录并显示“等待窗口激活”，不能使用预览几何替代，不能用缺失信息覆盖旧记录。

首次安装时若窗口从未得到可信尺寸，应标记未学习；允许引导用户逐组激活完成初始采集。此过程必须在首次设置中明确说明。

窗口处于最小化或隐藏状态时，不为恢复而自动展开或抢焦点；允许待再次可访问时恢复。

## 5. R03 自动记忆与保护

默认模式为“自动记忆 + 可锁定基准 + 历史回退”。

用户完成拖动或缩放、布局稳定后记录到当前组合。用户仍可一键保存、重命名、锁定基准。锁定后自动变化不能覆盖基准。

显示器插拔、唤醒、登录和恢复期间暂停学习。配置尚未稳定时不执行中间组合的恢复，不把系统挤压后的布局当成新偏好。

无法可靠区分主动调整与系统变化时，宁可保留原基准，将变化作为候选待确认。安全优先于无感自动化。

关闭窗口不能自动删除对应习惯；应用短暂无响应也不能导致布局被清空。

## 6. R04 布局恢复

已知配置稳定后恢复其专属布局。相同可用区域优先精确还原；可用区域变化时允许按比例适配，保证窗口可操作区域不会完全离屏。

跨屏窗口须有明确所属屏幕与适配规则。窗口相互左右、上下关系由位置还原，不承诺恢复完整遮挡层级或焦点顺序。

恢复前显示目标摘要并保留可撤销记录。自动恢复需用户启用；有歧义时只跳过受影响窗口，其余可安全恢复。

恢复后检查实际结果。有限次重试后仍失败，显示应用拒绝、尺寸限制、权限失效或窗口消失等原因，不得一直争抢窗口。

## 7. R05 登录与延迟窗口

布局在应用退出、系统重启后保留。提供可选登录启动。登录时等待屏幕稳定，不依赖一次性固定延迟。

应用和窗口陆续出现时逐个恢复，包括登录数分钟后手动打开的应用。没有出现的窗口保留待恢复记录，不能当成已完成。

“打开应用”作为可选功能，不默认启动所有应用；应用内部文稿与会话重建依赖应用自身能力。

## 8. R06 多窗口身份

一个应用的多个文档、多个浏览器窗口分别记忆；不同应用身份隔离，即使显示名称相同也不能混用。

重新登录后不能依赖旧进程编号、旧窗口编号或窗口枚举顺序。窗口标题改变、标题相同或无标题时，匹配必须保守。

候选存在歧义时显示待确认，允许用户建立窗口角色/匹配规则；不得把两个窗口分配到同一保存位置并宣称成功。

无法通用区分的窗口明确列入兼容性限制，不宣称所有应用所有窗口百分之百还原。

## 9. R07 控制与诊断

提供当前显示配置、布局、每个窗口的学习/恢复/待激活/歧义/失败状态。

提供保存、恢复、暂停、锁定、应用排除、取消待恢复和撤销最近恢复。配置变化后旧撤销不应盲目应用到新屏幕环境。

权限缺失或被撤销时停止相关读写，显示如何通过系统设置授权，不绕过 macOS 权限控制。

## 10. R08 数据与隐私

布局和历史仅保存在本机，支持用户主动备份和导出。升级保留用户数据；损坏时报告并保留损坏文件，不能用空布局覆盖历史。

不收集截图或窗口正文，无遥测，无自动云同步。窗口标题和文档路径按敏感信息处理，诊断默认脱敏。

测试与公开仓库仅使用合成数据，禁止提交用户真实布局、显示器序列号、私人标题、文稿路径和签名凭证。

## 11. 非功能需求

- 性能属于 P0 验收门槛，不能以功能完成为由忽略低 CPU、低内存要求。
- 单个无响应应用不得让整个界面无限卡住。
- 目标恢复时间：配置或窗口可访问状态稳定后 10 秒内完成或显示明确状态；等待台前调度激活不计作已完成。
- 兼容系统与架构依据实际构建和测试结果声明，不用“支持所有 macOS”代替验证。
- 不要求关闭 SIP、不要求 root 权限、不默认关闭台前调度。
- 界面优先中文，核心状态不只用颜色区分；支持键盘基本操作。

### 性能预算与测试口径

以下为首版目标预算，必须实测，不是当前性能结果。用户明确要求低内存、CPU 尽量接近零。绝对零资源占用不作承诺。

| 场景 | 目标预算 |
| --- | --- |
| 稳定空闲 10 分钟，设置界面关闭 | 进程平均 CPU ≤ 0.1%，按单逻辑核 100% 口径 |
| 稳定空闲 10 分钟 | 平均进程唤醒 ≤ 1 次/秒；应用自有周期性全量窗口扫描为 0 |
| 三屏、约 20 应用/50 普通窗口，预热完成 | 物理内存占用目标 ≤ 50 MiB，RSS 另列，不混用两个口径 |
| 设置界面关闭后 | 释放非必要展示资源，不保留无上限预览缓存 |
| 持续拖动或系统事件风暴 | 不随事件数量无限增长队列或内存，不逐事件写盘 |
| 稳定空闲 | 不做无变化的周期性布局落盘，不产生持续增长日志 |
| 1,000 次合成变化及 8 小时实机驻留 | 不出现持续内存增长；记录预热后及结束时内存、峰值、样本趋势 |
| 权限被拒绝、后台组不可访问、应用无响应 | 不忙等、不无限重试、不高频催促授权 |
| 睡眠期间及恢复暂停时 | 无后台轮询唤醒；暂停仍需保留明确标注的必要状态观察 |

性能报告必须记录 OS、芯片、屏幕/窗口数、采样时长、工具和统计口径，区分采样工具的开销。峰值 CPU 与持续时间分别列出，不以一次任务管理器截图宣称“零消耗”。

开启/关闭台前调度分别测试；压力测试包含连续显示变化、多个应用同时启动、无响应应用、权限撤销和窗口频繁更新。

如果安全恢复要求与性能预算发生冲突，先报告并调整方案，不静默降低安全性，也不擅自放宽预算。开发版未达到预算不能标记性能验收通过。

## 14. 已确认的产品决策

1. 默认采用自动记忆，同时提供锁定基准与历史回退。
2. 第一次使用时允许逐组激活台前调度窗口，完成真实几何学习。
3. 重启恢复针对已重新出现的窗口；自动启动应用可选，不承诺通用文稿/标签恢复。
4. 身份不明确时暂停该窗口恢复，允许手动映射，优先保证不搬错。

两种模式均为 P0 范围，测试报告必须分别列出结果。技术设计正在评审；实现须在技术设计确认后继续。台前调度相关可行性须先验证，不得用模拟测试代替实机结论。
